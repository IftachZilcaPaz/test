# reynovation: איך הסטודיו עובד באמת (בלי שאני מאחורי הקלעים)

ההחלטה: **שני חלקים**.
1. **אתר תדמית של reynovation**: המותג שלנו, העיצוב הלילכי. בלי יצירת AI. מסביר ומפנה לאפליקציה.
2. **אפליקציית ההפקה בתוך Higgsfield**: שם הלקוח מפיק בפועל.

## למה ככה: חיבור בלי מפתחות API

| מה צריך | איך זה מתחבר | מי משלם |
|---|---|---|
| כניסה | "התחברות עם Higgsfield", כפתור אחד | – |
| כתיבת התסריטים (AI טקסט) | שירות ה-LLM של Higgsfield מתוך האפליקציה (`createLlmClient`) | הקרדיטים של הלקוח |
| קריינות, סצנות מצולמות, תמונות | ה-SDK של Higgsfield (`createJobClient`) | הקרדיטים של הלקוח |
| הרכבת הסרטון (ffmpeg, כיתובים, סנכרון) | "קונטיינר" של האפליקציה, שמריץ את המנוע שלנו | חישוב של הפלטפורמה |
| שמירת פרויקטים, מילון הגייה, היסטוריה | מסד נתונים של האפליקציה (D1), וקבצים גדולים ב-R2 | – |

**אין שום מפתח API לנהל.** הלקוח מתחבר עם החשבון שלו, והפלטפורמה מחייבת את הקרדיטים שלו.
לפי כללי הפלטפורמה, אפליקציה שמייצרת AI לא יכולה לבקש מהלקוח להדביק מפתח משלו, וגם אין צורך.
לכן "חיבור קל של API של אנשים" = כפתור התחברות אחד.

## מה נשאר מהעבודה שעשינו

- **הסטודיו (4 השלבים, תמחור לפני כל צעד, ניקוד, בדיקות)**: עובר לאפליקציה כמו שהוא מבחינת ההתנהגות.
- **המנוע** (`video/engine`): עובר לקונטיינר. היום הוא משתמש ב-`higgsedit`, שקיים רק בסביבת
  העבודה שלי. בקונטיינר מחליפים אותו בהרכבה ב-ffmpeg ובכרום (Playwright). Whisper והכיתובים כבר עובדים ככה.
- **המחולל** (`video/generator`): הפרומפט והבדיקות עוברים כמו שהם. במקום Claude API קוראים ל-LLM של Higgsfield.

## מגבלה שחשוב לדעת

אפליקציה בתוך Higgsfield **חייבת להיראות כמו מוצר של Higgsfield** (ערכת העיצוב שלהם, Quanta).
העיצוב הלילכי והדמות נשארים באתר התדמית של reynovation, והאפליקציה נראית "Higgsfield עם השם שלנו".

## שלבי בנייה

1. אתר תדמית reynovation (עיצוב לילך, דמות, הסבר, מחירון, כפתור "להפקה").
2. אפליקציה: התחברות, קרדיטים, פרויקט, העלאת מסכים, כתיבת תסריט עם אישור עלות.
3. קריינות וסצנות דרך ה-SDK, עם אישור לפני כל תשלום (הפלטפורמה מחייבת חלון אישור).
4. קונטיינר עם המנוע: טיוטה, דף בדיקה, סרטון סופי.
5. פרסום בפיד הקהילה של Higgsfield (אופציונלי).
